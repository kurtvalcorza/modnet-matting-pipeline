## Two things this tutorial does that most of the fleet's others do not

**It converts a legacy pickled checkpoint in the runtime and says so.** The upstream file is a five-stream `torch.save` pickle, not a zip archive; Section 3 prints the static audit (the four globals the streams would import, 0 violations, the pinned audit digest) and the conversion record (751 source tensors, the 312 aliased backbone tensors dropped, the converted file's digest) before the model loads, and the provenance export records `served_from_pickle: false`.

**It adapts a photographic model to drawings, and downloads no image.** The labelled portraits are rendered because no photographic matting dataset with alpha mattes is both permissively licensed and free of personal-data concerns, and the public-domain photographs the row first pinned on Wikimedia Commons cannot be fetched from shared cloud runtimes (HTTP 429 on Kaggle, 2026-09-20); the paired held-out comparison is large by construction (a domain shift), the frozen and adapted mattes of two held-out portraits are written beside their exact alphas, and a real portrait is matted only when the learner uploads one through `USE_BYOD_PHOTO` (the frozen-versus-adapted matte difference is printed as an observation).

## Conformance notes

- **Standalone carrier (ST1–ST8):** the primary path performs no clone, repository install, or repository import; its only network peers are the Hugging Face Hub (the checkpoint at an immutable revision) and PyPI. Section 2 embeds the repository's 4 modules (`metrics.py`, `modeling.py`, `pipeline.py`, `samples.py`) verbatim in topological dependency order (each tagged `metadata.dimer.embedded_module`; the only rewrites make `DEFAULT_WEIGHTS_DIR` working-directory-relative and remove internal relative package imports), Section 3 carries the 1-file snapshot manifest inline and asserts it against the module's constants before fetching, and `NOTEBOOK_SOURCE` records the repository, revision and module digests in the exports.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried modules, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD9):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entry that is absent, from the Hugging Face Hub at the immutable revision (never `main`); `verify_snapshot` re-hashes it and asserts the checkpoint's digest against the package constant; `ModNetMattingPipeline.from_pretrained(weights_dir=..., report=print)` audits and converts the pickle when the safetensors file is absent, verifies it against the pinned digest, builds the vendored architecture and loads it strictly. The pickle is unpickled exactly once, in that conversion, through torch's weights-only loader, after the audit.
- **Stages (§4.1):** `sample_dataset` (rendered in the kernel) / `load_byod_dataset` (sample acquisition) → `dataset_manifest` + `validate_dataset` refusal probes (validation, with the ceilings and a dataset digest) → roles from disjoint seed ranges (train / validation / test) → `pipe.evaluate` on the frozen model with the constant baselines and `pipe.predict` on two held-out portraits (baseline) → `pipe.adapt` (bounded fine-tuning of the matting branches) → `pipe.evaluate` on validation and test with the four-way comparison (evaluation) → `pipe.predict` on the same portraits again and, through `USE_BYOD_PHOTO`, on the user's photograph (inference) → `pipe.save_artifact` → `ModNetMattingPipeline.from_artifact` with the parity assertion (export and reload).
- **Score semantics (UNC1–UNC4):** the matte is the fusion branch's sigmoid output, labelled uncalibrated; no threshold is applied, and the notebook says any binarisation and its cost trade-off are the deployment's to set.
- **Baselines and evidence (EVAL6/EVAL10/EVAL11):** the all-background and all-foreground mattes are scored on the same references as every model number, and every metric is labelled as per-image tutorial sample-sanity evidence from 20 drawn test portraits with no dispersion estimate.
- **Split integrity (SPL1–SPL8):** roles come from disjoint seed ranges, never from shuffling a pool; validation metrics select the epoch and the test portraits are used for nothing but the final evaluation; `check_split_disjoint` refuses a record present in two splits by id or by image bytes. In BYOD mode the seeded split is by record and the notebook says to keep the same person out of two splits.
- **Ceilings (VAL6):** the inference size range, the 512 × 512 labelled-record size, the alpha range and the record range are stated in the Prerequisites and printed from the schema before the model runs; three refusals are demonstrated.
- **BYOD (DAT10–DAT19):** `USE_BYOD` and `USE_BYOD_PHOTO` default to `False` so the sample path never opens an upload dialog; when enabled, user pairs flow through the same validation, baseline, adaptation, evaluation, inference, export and reload cells, and a user's photograph through the frozen and adapted models. The expected zip layout, the alpha convention and the privacy guidance — photographs of identifiable people without consent are restricted data — are stated in the Prerequisites and in Sections 4 and 8, and a sample pair is written to `outputs/` in that shape.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
